## 最優先(今日中に着手)

待ち時間が発生し、こちらの作業では短縮できないものです。着手が遅れた分がそのまま納期に効きます。

- [ ] **① Apple Developer Program に申請**(年 $99)
      TestFlight を使うのに必須。承認まで1〜3営業日。**これが通らないと実機配信は一歩も進みません。**
      個人名義なら Apple ID だけで申請可。法人名義は D-U-N-S 番号が必要で、未取得なら数日〜2週間かかります。
- [ ] **② 独自ドメインを取得**(年 ¥1,000〜4,000)
      お名前.com / ムームードメイン等。第2候補まで用意。
      メール送信とアプリのリンク解決(パスワード再設定)の両方に使うため必須です。
- [ ] **③ 9/20 の受入定義について成田様と合意**
      App Store での一般公開は9/20に間に合いません(審査 + Android は Play のクローズドテスト14日間)。
      9/20 は「TestFlight で実機動作を確認いただく」形への読み替えが必要です。**早いほど調整が楽です。**

## 今日〜明日(60〜90分で終わります)

3つとも GitHub でサインインするので、続けてやるのが速いです。

- [ ] **④ GitHub アカウント作成**
      2FA を有効化し、リカバリーコードを保管。
      リポジトリ `fitgym-app` を **Private・空**(READMEのチェックは外す)で作成。
- [ ] **⑤ Supabase プロジェクト作成**
      「Continue with GitHub」でサインイン → Organization `FitGym` → New Project。
      **Region は `Northeast Asia (Tokyo)`**。ここを間違えると作り直しです。
      DBパスワードを生成して保管し、Settings → API から Project URL / anon キー / service_role キーを控える。
- [ ] **⑥ Vercel アカウント作成**
      「Continue with GitHub」→ リポジトリアクセスを承認。Hobby(個人)で開始。

## ドメイン取得後(反映待ちが出るので早めに)

- [ ] **⑦ Resend に登録し、送信ドメインを認証**
      Domains → Add Domain → 表示された **SPF / DKIM / DMARC** レコードをDNSに追加 → Verify。
      **反映まで数十分〜最大48時間。** ここは待つしかありません。
- [ ] **⑧ Resend の API キーを発行**(権限は Sending access)
- [ ] **⑨ 送信元アドレスと表示名を決める**(例:`noreply@ドメイン` / 「FitGym 事務局」)

---

## Apple の承認が下りたら(ブラウザだけで完結・Mac 不要)

- [ ] **⑩ App ID を登録** — Developer サイト → Identifiers → `jp.fitgym.app`
- [ ] **⑪ App Store Connect にアプリを登録**
      マイ App → + → iOS / 名前 FitGym / 主要言語 日本語 / バンドルID `jp.fitgym.app` / SKU は任意
- [ ] **⑫ App Store Connect API キーを発行**
      ユーザとアクセス → インテグレーション → App Store Connect API → +
      **アクセス権は App Manager 以上**(これ未満だと証明書の自動生成に失敗します)
      **`.p8` は一度しかダウンロードできません。** キーID と Issuer ID も控える。
- [ ] **⑬ Team ID を確認** — Developer サイトのメンバーシップ画面にある10文字の英数字
- [ ] **⑭ 成田様を内部テスターに招待**
      App Store Connect にユーザー登録 → TestFlight 内部テスターに追加。
      成田様側で Apple ID と、iPhone への TestFlight アプリのインストールが必要です。
      内部テストは**審査不要**で、アップロード処理が終わり次第すぐ配信されます。

## GitHub にシークレットを登録(⑤と⑫が終わってから)

リポジトリ → Settings → Secrets and variables → Actions → New repository secret

- [ ] `APPSTORE_KEY_ID`
- [ ] `APPSTORE_ISSUER_ID`
- [ ] `APPSTORE_PRIVATE_KEY`(`.p8` の中身を `-----BEGIN PRIVATE KEY-----` の行ごと全部)
- [ ] `APPLE_TEAM_ID`
- [ ] `VITE_SUPABASE_URL`
- [ ] `VITE_SUPABASE_ANON_KEY`
- [ ] `VITE_PASSWORD_RESET_URL`

`service_role` キーと Resend の API キーは**チャットに貼らず**、Vercel の環境変数画面に直接入力してください。
こちらは環境変数名だけ指定します。

## 成田様との合意事項

開発者の1アカウントに集約するため、着手前に文書で握っておくことを推奨します。

- [ ] **データの所有・管理** — 会員/予約データが開発者の Supabase 内に置かれること
- [ ] **費用負担** — 有料プランの決済が開発者カードになること、立替・請求の扱い
- [ ] **契約終了・移管時** — アカウント譲渡またはデータ移行の手順と費用
- [ ] **医療データ(最終モデル)** — その段階で店舗名義への分離を再検討すること
- [ ] **Android を出すか / 出すなら法人アカウントにするか**
      個人アカウントだと本番公開前に **12名以上 × 14日間連続のクローズドテスト**が必要です(法人は免除)。
      Android も出すなら法人アカウント(D-U-N-S 必要)を強く推奨します。
