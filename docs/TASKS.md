## 最優先(今日中に着手)

QR配布の前提になるものです。**HTTPS のURLが無いとQRが作れません。**

- [ ] **① GitHub アカウント作成**
      2FA を有効化し、リカバリーコードを保管。
      リポジトリ `fitgym-app` を **Private・空**(READMEのチェックは外す)で作成。
- [ ] **② Vercel アカウント作成**
      「Continue with GitHub」→ リポジトリアクセスを承認。Hobby(個人)で開始。
      → これで `https://〇〇.vercel.app` が発行され、**QR配布が可能になります**。
- [ ] **③ Supabase プロジェクト作成**
      「Continue with GitHub」でサインイン → Organization `FitGym` → New Project。
      **Region は `Northeast Asia (Tokyo)`**。ここを間違えると作り直しです。
      DBパスワードを生成して保管し、Settings → API から Project URL / anon キー / service_role キーを控える。

**①②③ は3つとも GitHub でサインインするので、続けてやると 60〜90分で終わります。**

## 今週中(反映待ちが出るので早めに)

パスワード再設定メールに必要です。QR配布自体は `vercel.app` のURLでできますが、
**独自ドメインが無いとパスワード再設定メールを実際に送れません**(Resend のテスト送信のみになります)。
9/20 のデモにパスワード再設定を含めるなら必須です。

- [ ] **④ 独自ドメインを取得**(年 ¥1,000〜4,000)
      お名前.com / ムームードメイン等。第2候補まで用意。
- [ ] **⑤ Resend に登録し、送信ドメインを認証**
      Domains → Add Domain → 表示された **SPF / DKIM / DMARC** をDNSに追加 → Verify。
      **反映まで数十分〜最大48時間。** ここは待つしかありません。
- [ ] **⑥ Resend の API キーを発行**(権限は Sending access)
- [ ] **⑦ 送信元アドレスと表示名を決める**(例:`noreply@ドメイン` /「FitGym 事務局」)

## 成田様との合意事項

- [ ] **9/20 はデモ(PWA)である旨の共有**
      App Store / Google Play への掲載は法人化後になること、9/20 は QR からホーム画面に置く形になること。
- [ ] **データの所有・管理** — 会員/予約データが開発者の Supabase 内に置かれること
- [ ] **費用負担** — 有料プランの決済が開発者カードになること、立替・請求の扱い
- [ ] **契約終了・移管時** — アカウント譲渡またはデータ移行の手順と費用
- [ ] **医療データ(最終モデル)** — その段階で店舗名義への分離を再検討すること

### ストア展開に向けて(法人化の進行と並行)

- [ ] **法人化の完了時期の共有** — これが App Store 展開の起点になります
- [ ] **D-U-N-S 番号の取得**(無料・通常5営業日、Apple 経由だと最大2週間)
      Apple の Organization アカウントと Google Play の組織アカウント、両方で必要です。
- [ ] **ストアのアカウント名義は成田様の法人**、開発者はメンバーとして招待いただく形にする
      理由:ストアの「販売元」表示、規約上の責任の所在、契約終了時の引き継ぎのしやすさ。
      Google Play の組織アカウントは **12名×14日のクローズドテストが免除**されます。
- [ ] **プライバシーポリシー** — ストア公開に必須。9/20 のデモでは不要です。
